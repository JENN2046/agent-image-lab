## Classification Bands

Use these bands only for planning future narrow splits:

| Band | Prefix or theme | Movement note |
| --- | --- | --- |
| `exact_new_trial` | `validate_exact_new_trial_*` | Split only after memory, DailyNote, provider, archive, and approval boundaries are separated. |

| `review_and_visual_workflow` | review report, visual asset, sample registry, prompt package | Candidate for later visual workflow subindexes. |
| `adapter_and_bridge` | adapter, VCP bridge, VCPChat, VCPToolBox, PVOS | Preserve no-real-read and no-exec boundaries. |
| `misc_governance` | MVP, smoke, checkpoints, repository governance | Split only when references are mapped. |

## Movement Rule

Before moving any `other` validator family:

- pick one classification band only
- map all root references, package references, aggregate validator references,
  and historical status references
- keep root compatibility wrappers until consumers are migrated
- extend `scripts/validators/VALIDATOR_INDEX.md` and the repository structure
  governance validator in the same slice
- validate without provider/plugin/API/image/memory/runtime side effects
