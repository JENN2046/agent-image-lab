## Objective

Create a docs-first convergence plan for capsule product-core validator/code debt
and decide the first repair target from current repository evidence.

The priority rule for this plan is strict: first verify whether accepted capsule
creator output matches the accepted manifest requirements enforced by
`scripts/lib/capsule_manifest_contract.js`.

### Accepted Creator / Manifest Contract Parity

`scripts/lib/capsule_manifest_contract.js` requires accepted manifests to carry
these top-level false fields:

```yaml
accepted_top_level_required_false:
  - production_candidate_allowed
  - memory_write_allowed
  - DailyNote_write_allowed
  - VCP_memory_write_allowed
  - commercial_delivery_allowed
```

The validator enforces those fields in `validateCapsuleManifest()` by iterating
the accepted lane's `ACCEPTED_TOP_LEVEL_FALSE_FIELDS` and checking each top-level
manifest field is exactly `false`.

Current checked-in accepted capsule manifests contain those fields. That proves
the existing archived accepted capsules are aligned with the contract.

However, `scripts/create_preview_capsule.js` writes the accepted capsule
`manifest.json` with `manifest_type`, `version`, `sample_id`, `created_at`,
`artifact`, `chain`, `source_refs`, and `guard`, but it does not write the
accepted top-level false fields listed above.

Decision:

```yaml
creator_contract_parity_drift_exists: true
drift_type: accepted_creator_output_omits_contract_required_top_level_false_fields
why_this_matters: >
  Existing accepted manifests can pass because they already contain the fields,
  while a future fresh accepted capsule generated by the creator would be likely
  to fail the current manifest contract. That is product-core output drift, not
  merely validator organization debt.
```
