# Autopilot Failure Recovery

```yaml
recovery_id: A4_8_failure_recovery
scope: local_safe_project_operation
```

## Recovery Rules

When A4.8 encounters a problem, Codex may make one narrow local fix only if the fix is obvious, reversible, inside the current allowlist, and does not cross a hard stop.

If the fix is not obvious, stop and report the blocker.

## Common Failure Modes

| Failure | A4.8 Behavior |
|---|---|
| Dirty worktree before edits | Stop, report dirty files, do not edit. |
| Unexpected file appears in diff | Stop unless it is clearly generated by the current task and allowlisted. |
| Validation fails | Attempt one narrow obvious fix if in scope; otherwise stop. |
| Push rejected | Stop; do not rebase/reset/force push automatically. |
| Secret or `.env` risk appears | Stop and report sanitized path only. |
| Scope expands into provider/runtime/image/memory | Stop and request explicit authorization. |
| `.agent_board` freshness drift | Repair only if `.agent_board` is allowed for the current task. |
| Missing validation tool | Record validation gap; do not invent broad runtime checks. |

## Stop Report

```yaml
failure_recovery_closeout:
  status: blocked
  reason:
  hard_stop:
  files_changed:
  validation_run:
  validation_failed:
  safe_state:
  required_human_action:
```

## Non-Recovery Actions

A4.8 must not recover by running provider calls, image generation, secret reads, runtime commands, force push, reset, rebase, dependency installation, or destructive cleanup.
